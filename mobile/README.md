# Verifact Mobile (Capacitor)

Native Android + iOS shell for Verifact. It is intentionally thin: the app runs
the **live website** (`https://verifact.ro`) inside a native WebView, and adds
the one thing the web cannot do — a real OS **share target**, so a user who sees
a suspicious post in TikTok / Facebook / WhatsApp can tap **Share → Verifact**
and land on the site with the claim pre-filled and ready to verify.

Nothing in the main Next.js app changes. The integration seam is the existing
query parameter: `VerifyTool` already reads `?text=` (also `?claim=`, `?q=`) and
fills the claim box. The mobile shell just navigates to
`https://verifact.ro/?text=<shared text>`.

```
mobile/
  capacitor.config.ts   # app id, name, local webDir
  package.json          # Capacitor + send-intent deps
  www/index.html        # bootstrap: read share intent → open the site pre-filled
  android/  ios/         # generated by `cap add` (see below), gitignored by default
```

## 1. Install

```bash
cd mobile
npm install              # already-committed deps: Capacitor + send-intent + filesystem
npx cap sync             # re-copies www/ + plugins after any www change (safe to re-run)
```

You do **not** need `npx cap add android` — the project is already here. Only run
it to regenerate from scratch (it would overwrite the manifest/icon work).

## 2. Share target

The `send-intent` plugin captures the OS share; each platform lists Verifact in
the share sheet via manifest entries. Bundling a real native project (not a
`server.url` wrapper) is what lets the plugin run.

### Android — done

`android/app/src/main/AndroidManifest.xml` already contains both filters:

```xml
<intent-filter>
  <action android:name="android.intent.action.SEND" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="text/plain" />
</intent-filter>
<intent-filter>
  <action android:name="android.intent.action.SEND" />
  <category android:name="android.intent.category.DEFAULT" />
  <data android:mimeType="image/*" />
</intent-filter>
```

### iOS — Share Extension (Mac / Xcode)

After `npx cap add ios` on a Mac, follow the plugin's iOS guide
(<https://github.com/carsten-klaffke/send-intent#ios>) — do **not** hand-copy the
Swift from memory, use the plugin's current `ShareViewController.swift` for your
installed version. Concrete steps:

1. **Add the target:** Xcode → **File → New → Target → Share Extension**, name it
   e.g. `ShareExtension`.
2. **App Group** (lets the extension hand the payload to the app): enable
   *Signing & Capabilities → App Groups* on **both** the app target and the
   extension target, with the same group id `group.ro.verifact.app`.
3. **Swift:** replace the generated `ShareViewController.swift` with the plugin's
   version (linked README).
4. **Activation rules** — in the extension's `Info.plist`, under
   `NSExtension → NSExtensionAttributes → NSExtensionActivationRule`, accept text
   *and* images so the shell's screenshot path works:

   ```xml
   <key>NSExtensionActivationRule</key>
   <dict>
     <key>NSExtensionActivationSupportsText</key>
     <true/>
     <key>NSExtensionActivationSupportsWebURLWithMaxCount</key>
     <integer>1</integer>
     <key>NSExtensionActivationSupportsImageWithMaxCount</key>
     <integer>1</integer>
   </dict>
   ```

5. Run on device from Xcode, then test: share text and a screenshot from another
   app → **Verifact** should open pre-filled.

## 3. Run it

```bash
# Android — device or emulator
npx cap run android

# iOS — Mac only
npx cap open ios     # then Run from Xcode
```

Test the flow: open another app, share some text, pick **Verifact** in the share
sheet. The app should open on `verifact.ro` with the text already in the box.
Then share a **screenshot** — the shell reads the image, sends it to `/api/ocr`,
and opens the site pre-filled with the extracted text.

After any change to `www/` or `capacitor.config.ts`, re-run `npx cap sync`.

### Screenshot sharing — how it works & caveats

The bootstrap (`www/index.html`) reads the shared image's bytes with
`@capacitor/filesystem`, base64-encodes them, and POSTs to
`https://verifact.ro/api/ocr` (CORS-enabled for the shell's origin — see the web
app's `src/lib/api/cors.ts` and the `ALLOWED_EXTENSION_ORIGINS` env var). The OCR
text becomes `?text=` on the site. On OCR failure it opens the site plain so the
user can retry manually.

- `/api/ocr` accepts **JPEG, PNG, WEBP** only. iOS/Android *screenshots* are PNG,
  so the main case works. A shared **photo** may be HEIC (iOS) and will be
  rejected — acceptable for v1; convert-before-OCR is a later refinement.
- Reading `content://` URIs on Android needs a current `@capacitor/filesystem`.
  If `readFile` can't resolve the shared URI on some device, the shell falls back
  to opening the site plain (no crash).

## 4. App identity

- **App ID:** `ro.verifact.app` (in `capacitor.config.ts`; must match the store
  listings and the iOS App Group prefix).
- **Icons / splash:** already generated for Android from
  `mobile/assets/icon.png` (Verifact "V" logo, from `public/logo/`) via
  `@capacitor/assets` — light + dark. To regenerate or extend to iOS after
  `cap add ios`:
  `npx @capacitor/assets generate --iconBackgroundColor '#ffffff' --iconBackgroundColorDark '#0b0b0c' --splashBackgroundColor '#ffffff' --splashBackgroundColorDark '#0b0b0c'`.

## 5. Signing & store submission

- **Android:** in Android Studio, *Build → Generate Signed Bundle (AAB)*. Keep
  the keystore safe — losing it blocks future updates. Upload the AAB in the
  [Play Console](https://play.google.com/console).
- **iOS:** in Xcode, set your Team, *Product → Archive*, then upload to App Store
  Connect.

### ⚠️ Avoiding a "just a website wrapper" rejection

Apple (guideline 4.2) and Google both reject apps that are only a WebView around
a site. Our defense is that the **share target is genuine native functionality**
— make sure it works before submitting, and in the review notes describe the
share-to-verify flow explicitly (with steps to reproduce). If review still
pushes back, the next increment is native screenshot capture + push
notifications (both listed below), which clearly cross the "native value" bar.

## Roadmap (not built yet)

These are deliberately out of scope for the first shell. Each is a clean
follow-up:

1. **Push notifications** for trending claims (`@capacitor/push-notifications`).
2. **Native share of a finished report** (share the verdict back out).
3. **Offline "history" of past checks** cached on device.
4. **HEIC → JPEG conversion** before OCR, so shared iOS *photos* (not just
   screenshots) verify too.

**Done:** share **text/links** and share **screenshots** (OCR'd via `/api/ocr`),
both landing on the site's existing `?text=` claim input.

## Why this shape (design notes)

- **Live site, not a rebuilt UI.** The web app is SSR Next.js with streaming
  verification; re-implementing it in React Native would be months of duplicate
  work for no user-visible gain. The WebView shows the real thing, always current.
- **Local bootstrap, not `server.url`.** Loading a bundled local page first lets
  the Capacitor bridge and `send-intent` run so we can capture the share, then we
  navigate to the site. A pure remote `server.url` would give us nowhere to run
  that code.
- **Zero coupling to the web app.** The only contract is the `?text=` query
  parameter the site already supports. Change nothing in `src/` to ship this.
